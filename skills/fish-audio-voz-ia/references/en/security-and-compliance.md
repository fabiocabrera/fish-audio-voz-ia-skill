# Security and compliance

## Security

- The API key lives in an environment variable on the server or in a local file **outside** the repository. Never in code, Git, screenshots or chat.
- If the key leaks, generate a new one in the Fish Audio dashboard and revoke the old one.
- Do not put client text or personal data in test requests. The free model may keep submitted text to improve the service; read the current policy.
- Log errors without printing the key or the whole response body.

## Compliance

- **Commercial use:** the website's free plan may restrict use to personal purposes, and the pricing documentation may disagree. Read the current terms before using it in paid or client work; when in doubt, use the paid plan, which usually costs very little per short video.
- **Third-party voices:** only clone or use the voice of someone who authorized it in writing. Do not imitate public figures.
- **AI-generated content:** follow the rules of the platform where you publish (Instagram, YouTube and others ask for synthetic content to be labeled in some cases).
- **No promise of results:** the voice improves the viewer's experience; it does not guarantee reach, sales or retention.
- **Availability:** free models often carry no uptime guarantee. Plan a fallback voice.
